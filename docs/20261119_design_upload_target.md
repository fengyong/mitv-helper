# 产品设计：上传可指定存放位置（v2）

- 日期：2026-11-19（v2 修订同日）
- 状态：**评审修订 v2 · 决策已闭合**（D1–D7 见 §12；进入实现排期前需复审确认）
- 关联：`docs/ARCHITECTURE.md` §2 智能分流；`Sources/MiTVApp/SmartRouting.swift`（2026-11-19 定案的硬编码分流，本设计将其扩展为"可指定"）

---

## 1. 背景与问题

当前所有上传遵循硬编码的智能分流：视频 → 电视 `/Movies`，照片 → 电视 `/Pictures`，其他文件 → 根目录（`SmartRouting.destinationDir(kind:)`）。用户无法干预落点。

典型痛点：想把一整部剧（几十个视频文件）传到电视上自己整理的目录（如 `/电视剧/庆余年2`），目前只能全部堆进 `Movies`，再在电视端手动整理——文件一多基本不可操作。

## 2. 目标与非目标

**目标**
1. 用户可以把上传目标指定为电视上任意**已存在**的目录。
2. 指定一次后持续生效，直到用户改回默认，不为每次上传增加操作负担。
3. 默认行为（智能分类）完全不变，新能力零学习成本、不干扰现有用户。

**非目标（本期不做）**
- 不做递归建目录（FTP MKD 不支持多级创建，且真机电视不支持 MKD）。
- 不做"按类型在指定目录下再分子目录"的混合规则。
- 不做下载侧的目标目录改造（下载已有本地目录记忆）。
- 不改 CLI（`mitvctl` 的 upload 目标路径后续单独评估）。
- 不做卡片级改位置（V1.1 再评估，见 §5.4；首版优先级保持两层，不让用户持有三层 override 心智模型，D2）。
- 不做「上传到这里」内的照片图库入口（V1.1 再评估；组合路径已覆盖能力，见 D5）。

## 3. 已确认的产品决策（2026-11-19 内部对齐）

| 决策点 | 结论 |
|---|---|
| 主交互模型 | **常驻"存放位置"切换器**：传前设置、传时无感，不用每次选 |
| 混合批次 | 指定位置时，**一批内所有文件（含视频/图片/其他类型）全部进指定目录** |
| 首版入口范围 | 常驻切换器 + 选择器（含最近位置快切）+ 浏览页「上传到这里」+ 设置页同步；**卡片级改位置 defer V1.1**（D2） |
| 新建文件夹 | **按能力显示**：`caps.mkdir=true` 才显示；真机 MKD 550（mkdir=false）隐藏，不摆必失败按钮；toast 只留探测后能力变化的竞态（D1） |

## 4. 核心概念：存放位置

"存放位置"是一个全局二态状态（跨启动持久化）：

```
┌─ 智能分类（默认，现状行为）──────────────────────────┐
│  视频 → Movies    照片 → Pictures    其他 → 根目录   │
└─────────────────────────────────────────────────────┘
┌─ 指定位置 ──────────────────────────────────────────┐
│  所有上传（不分类型）→ 用户选定的电视目录            │
└─────────────────────────────────────────────────────┘
```

- 切换器对**之后**的批量上传生效；已入队的任务不受影响（首版无卡片级改位置，D2；要改落点用浏览页「上传到这里」重新入队）。
- 指定位置只能选电视上已存在的目录；目录被删/掉盘属于异常场景，走降级（§6.3）。

## 5. 交互设计

### 5.1 常驻「存放位置」切换器（主入口）

主窗口顶部导航栏（`HeaderBar`，照片/视频/电视页签旁）新增一个胶囊 chip，任何页面可见：

```
┌────────────────────────────────────────────────────┐
│ [照片] [视频] [电视]    〔存放位置：智能分类 ˅〕 ◉已连接 │
└────────────────────────────────────────────────────┘
指定模式下变为：
│ [照片] [视频] [电视]    〔存到：庆余年2 ˅〕      ◉已连接 │
```

- 智能分类模式显示"智能分类"；指定模式显示末级目录名 + 悬停 tooltip 展示完整层级（如 `电视剧/庆余年2`）（D4 已闭合：不直接显示全路径，header 留白珍贵）。
- 点击 chip → 打开「选择存放位置」弹窗（§5.2）。
- 未连接电视时点击 → toast："先连接电视才能选择存放位置"。

### 5.2 「选择存放位置」弹窗（新组件）

Sheet 呈现（风格同设置页/照片选择器），零术语：

```
┌─ 选择存放位置 ──────────────────────────────┐
│                                             │
│  (•) 智能分类                                │
│      视频放进 Movies 文件夹，照片放进        │
│      Pictures 文件夹，其他放根目录           │
│                                             │
│  ( ) 指定位置 —— 所有文件放进选定的文件夹    │
│      ┌───────────────────────────────────┐ │
│      │ 最近使用：[庆余年2] [电影] [根目录] │ │
│      ├───────────────────────────────────┤ │
│      │ 电视根目录 › 电视剧 › 庆余年2      │ │
│      │  📁 第1季                          │ │
│      │  📁 花絮                           │ │
│      └───────────────────────────────────┘ │
│      [＋ 新建文件夹]      当前所在：庆余年2  │
│                                             │
│                    [取消]  [使用此位置]      │
└─────────────────────────────────────────────┘
```

交互规则：
- 两个模式为单选；选中"指定位置"才展开目录浏览区。
- **导航式选择**：单击文件夹进入（与电视浏览页一致）；"使用此位置"作用于**当前所在目录**（面包屑末级），按钮旁实时显示当前所在目录名。选根目录 = 面包屑退回"电视根目录"。
- 只显示文件夹，不显示文件（数据源复用现有 `TVFileService.list`，目录优先排序；沿用 `BrowseFilter` 过滤系统目录）。
- **最近使用**：横向 chips，最多 5 个，点击直接把"当前所在目录"切过去。记录时机 = 每次确认"使用此位置"（指定目录）时；去重、最新在前。与电视绑定（存于该电视的持久化状态中，换电视自然重置）。
- **新建文件夹**：仅当 `caps.mkdir=true` 时显示（连接时已探测，与删除策略的能力分支同源，D1）。点击弹出输入框（默认名"新建文件夹"可改）→ 在当前所在目录下创建 → 成功则刷新并进入新目录；竞态失败（探测后能力变化）→ toast："这台电视不支持在电视上新建文件夹"。`mkdir=false`（真机 SwiFTP MKD 550 实测）时按钮整体隐藏：在唯一受支持的真机上它必然失败，摆出来等于训练用户碰壁。
- 确认"智能分类" = 恢复默认；确认"指定位置" = 写入全局存放位置。

### 5.3 浏览页「上传到这里」

电视文件浏览页底部操作条（`GlassActionBar`）新增按钮：

```
│ 电视根目录 › 电视剧 › 庆余年2              │
│  [第01集.mp4] [第02集.mp4] …               │
│         [ ⬆ 上传到这里 ]                   │
```

- 点击 → 打开本地文件/文件夹多选选择器（复用 `PickService.chooseMedia`，含文件夹递归展开、非媒体过滤）→ 该批文件以**当前浏览目录**为批级目标入队。
- 这是"批级一次性指定"，**不修改**全局存放位置。
- 当前在根目录时同样可用（传到根目录）。
- 完成后 toast："N 个文件即将存到 电视剧/庆余年2"。
- 首版不接照片图库入口（D5）：要把图库照片送进指定目录，走组合路径「chip 设指定位置 → 主页从照片图库挑选」，能力不缺、只少一个入口；照片选择器为独立 sheet，接入成本留到 V1.1。

### 5.4 队列卡片改位置（V1.1 再评估，首版不做）

首版**不做**卡片级改位置（D2）。理由：它引入第三层 override（卡片 > 批级 > 全局 > 智能分类），用户要持有这套心智模型才能预测文件落点，违背「像 AirDrop 一样简单」；批级「上传到这里」+ 入队 toast 带落点（D3）已把误落点概率压得很低，传前纠正诉求可用「取消该批 → 重新入队」满足。

V1.1 再评估时的入口形态（仅记录，不排期）：queued 卡片「将存到 X/」可点击 → 纯目录选择（不带智能分类单选）→ 仅影响该卡片；已开传/已终结不可改。

### 5.5 设置页同步

设置页「存放位置」区块从纯文案变为可操作：

```
存放位置
当前：智能分类（视频进 Movies，照片进 Pictures，其他进根目录）
[更改…]                       （指定模式下追加：[恢复智能分类]）
说明：重名文件自动顺延编号；同名但内容不同的文件自动加指纹后缀。
```

"更改…"打开同一个 §5.2 弹窗，与 chip 完全同源。

## 6. 行为规则

### 6.1 目标目录解析优先级

实现上收敛为两层（批级目标在入队时即写入每个任务项；卡片级 override 首版不做，D2）：

```
任务项自带目标（「上传到这里」批级）
      ↓ 没有则
全局指定目录（存放位置 = 指定位置）
      ↓ 没有则
智能分类：视频 /Movies、照片 /Pictures、其他 /（现状，不变）
```

### 6.2 混合批次

全局指定位置时，一批内视频、照片、其他文件**全部**进指定目录（已确认的决策）。智能分类模式下维持现状分流。

**落点可见性（D3）**：指定模式下（全局或批级）入队 toast 带落点：「N 个文件即将存到 庆余年2」（批级文案见 §5.3，全局同文案）。全局模式是常驻隐藏状态——chip 可见 ≠ 后果可见；只有在动作发生时报出落点，才能消除「下个月的照片悄悄进了电视剧目录」这类惊讶。智能分类模式维持现状文案，不加噪。

### 6.3 指定目录不可用的降级链路

指定目录在上传时已消失（目录被删 / U 盘重插换名）：

```
直接 LIST 指定目录
  ├─ 成功 → 正常走重名判定与上传（复用现有链路，比智能分流少一次根目录 LIST）
  └─ 失败 → 尽力 MKD 创建最后一级
        ├─ 成功 → LIST 后正常上传
        └─ 失败（真机电视 MKD 550）→ 回退电视根目录
             + toast："指定的位置已不在电视上，文件已放到电视根目录"
```

- 重名顺延、同名相同文件跳过、同名不同文件加指纹后缀、GBK 兼容命名：**全部复用现有逻辑，零改动**。
- 并发互斥按目标目录计算（现有 `inflightUploadNames(dir:)`），跨目录同名不算冲突，天然正确。

### 6.4 未连接时的行为

- 未连接电视：拖入/选择的文件进入现有暂存机制（`pendingDropURLs`），连接成功后按**当时的**全局存放位置入队。
- 选择器只在已连接时可打开（chip 与设置页入口统一拦截 + toast 提示）。

## 7. 持久化设计

沿用 `TVPersistState`（`tv.json`，Codable JSON 原子写），新增两个可选字段，旧版本 JSON 缺字段自动按 nil 处理，**完全向后兼容**：

```swift
/// 全局自定义上传目录（nil = 智能分类）
var customUploadDir: String?
/// 最近使用的指定目录（最新在前，去重，上限 5）
var recentUploadDirs: [String]?
```

队列任务项 `QueueItem` 新增 `dirOverride: String?`（随队列 JSON 一并持久化），承载批级目标（「上传到这里」；卡片级 defer V1.1，D2）。

## 12. 决策记录（v2 闭合，2026-11-19）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 新建文件夹按钮按 `caps.mkdir` 显示，真机 550 隐藏 | 能力连接时已探测；摆必失败按钮 = 训练用户碰壁，违背「功能敢于不做」；删除策略的能力分支（DELE 不支持即禁用）是现成先例 |
| D2 | 卡片级改位置 defer V1.1，首版优先级两层 | 三层 override 心智模型违背「像 AirDrop 一样简单」；批级入口 + 落点 toast 已覆盖误落点纠正 |
| D3 | 指定模式（全局/批级）入队 toast 带落点 | 全局模式是常驻隐藏状态；chip 可见 ≠ 后果可见；动作时刻报落点消除惊讶 |
| D4 | chip 显示末级目录名 + tooltip 全路径 | header 留白珍贵（设计原则 5）；全路径截断是噪声；队列卡片已承载全路径 |
| D5 | 「上传到这里」照片图库入口 defer V1.1 | 组合路径「chip 设指定 + 主页从照片图库挑选」已覆盖能力，只少一个入口；独立 sheet 接入成本不低 |
